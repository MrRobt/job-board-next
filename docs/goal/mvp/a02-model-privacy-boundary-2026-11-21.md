# A02 · 模型请求前隐私格式双层阻断 · 2026-11-21

## 本包目标与变更

职讯集的模型调用流程原先在 `app/actions/career.ts` 表单入口检查普通邮箱、连续手机号与 18 位身份证号码，但带短空格、连字符或全角字符的常见输入可能漏检；而直接调用底层 `generate()` 时并没有再次检测，形成未来新增调用路径的绕过风险。

- `lib/career/contracts.ts` 的 `hasContact()` 现在先进行 Unicode NFKC 规范化，覆盖常见全角邮箱、带短分隔符或国际区号的中国大陆手机号以及分组书写的 18 位证件号码。
- `lib/career/provider.ts` 的 `generate()` 在检查模型可用性或执行 `fetch()` 之前，重新用服务器端 `input` Schema 校验入参并检查所有用户文本字段。拒绝后不发送模型请求、不产生模型费用、不给调用方返回敏感正文。
- 保留原有表单端检查，实现 **入口拒绝 + 模型出口拒绝** 双重保护；本轮不修改用户次数消费/退款逻辑、模型供应商配置和数据存储结构。

## 验收证据

- 新 `tests/career-privacy-boundary.test.ts` 两项：格式化手机号/分组证件/全角邮箱应拒绝；不含联系信息的真实岗位、技术和业绩说明可放行；**2/2 PASS**。
- 新 `tests/integration/ai-privacy-outbound.test.ts`：从底层直接调用 `generate()`，对含敏感格式或不满足长度 Schema 的输入必须抛错，且通过模拟 `fetch` 断言**0 次出站请求**；**1/1 PASS**。

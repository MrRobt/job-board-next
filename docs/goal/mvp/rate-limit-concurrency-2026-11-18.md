# P0 认证限流并发事务等待与故障失败关闭（2026-11-18）

## 现象和根因

本轮已通过的交易/支付/退款/认证集成测试在同一 MySQL 8 隔离库中并行执行时，`tests/integration/trusted-ip-limit.test.ts` 出现 Prisma 交互式事务建联等待超时，首轮完整套件 **16/17 PASS、1 FAIL**。这并非限流原子递增业务逻辑错误，而是在多项测试与 7 个并发相同 IP 请求竞争 Prisma/MySQL 连接时，`$transaction` 默认等待值不足。原实现直接抛出异常，可能导致认证请求返回 500。

## 修复

- 仅修改 `lib/rate-limit.ts`，保留此前已验收的 MySQL 原子 `INSERT...ON DUPLICATE KEY UPDATE` 和事务内读，避免重新引入 PRIMARY 唯一键竞态。
- 显式配置 Prisma 交互式事务 `maxWait: 10_000` 毫秒、`timeout: 15_000` 毫秒；有限等待连接，不无限阻塞。
- 数据库、连接池或事务出错时返回 `false`，**认证/注册/AI 滥用保护失败关闭**，绝不因 DB 异常跳过限流。无效限流配置仍会抛出异常，避免把代码配置错误误判为用户请求超额。
- 不更改任何真实支付、AI 开关或商户配置，也不触及他人退款 Schema/账户界面改动。

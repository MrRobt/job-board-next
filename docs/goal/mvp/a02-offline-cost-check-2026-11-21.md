# A02 · 模型成本对账输入一致性检查（2026-11-21）

## 背景和边界

接续 `a02-provider-usage-evidence-2026-11-21.md` 已验收的供应商 usage 解析模块。本次不重新开发 Token 解析，也不尝试突破此前受工作区安全检查限制的用量账本事务/数据库迁移。原有 Provider、资金、用户会话、支付开关均不修改。

新增 `lib/career/model-cost-check.ts`，是 **纯函数、脱敏数据离线核验**。输入：同一批准供应商+模型、已存在的内部唯一运行号、逐次调用的 `ModelUsageEvidence`、经运营获得但来源仍需外部验证的账单金额，以及经批准的价格策略。输出仅为聚合数量、金额（人民币整数分）和异常代码；**不包含提示词、简历、响应正文或任何 API 密钥**。

## 检查规则

1. 单批限定 1–10,000 条；对内部运行号去重、限定标识格式和同一供应商/模型范围，重复/伪造/错作用域直接拒绝。
2. 已报告用量必须具备合理的输入/输出 Token 整数；总数如已报告必须一致。用输入和输出 Token × **批准的输入/输出单价重新计算**整数分，不信任传入的 `costFen` 或 `overBudget`。
3. 未报告或无效用量不能伪装成 0 成本；该批标记 `REVIEW_REQUIRED`，`differenceFen=null`，等待人工补齐服务方记录。
4. 缺账单、已知金额不一致、任意调用超预算，均标记 `REVIEW_REQUIRED`；账单金额或样本异常、单价非法时直接拒绝。
5. 仅当样本完整、批准单价与逐条记录一致、没有超预算、输入账单与报价成本相同，才返回 `INPUT_MATCH`。**该状态仅表示两组输入数字算术一致，并非“真实供应商资金/账单核销”**，不能用于解除财务或上线人工审批。

## 本地测试证据

- `tests/model-cost-check.test.ts` 专项 **4/4 PASS**：正常整数分匹配、缺失或无效 Token 保持未知、超预算/无账单/金额不一致要求人工复核，以及重复运行号、非法价格、错作用域、篡改逐条成本/超预算标记一律拒绝。
- 本轮全量单元 **60/60 PASS**、隔离 MySQL 集成（文件串行）**31/31 PASS**、TypeScript exit 0、Next.js 16.4.6 生产 build exit 0。
- 全量测试计数包含其他 Agent 当时未提交的模型响应隐私安全测试；**本包自身只新增 4 个专项单元**，不混提交其他 Agent 文件。
- 没有向真实模型或商户发起任何请求，没有执行数据库迁移、用量持久化或正式财务对账。

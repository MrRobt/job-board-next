# /goal 职讯集 AI 求职工具平台商业 MVP 长期交付

> 版本：v1.0 · 生效：2026-11-17 · 工作区：`F:\code\job-board-next`

## 1. 不可更改的业务目标

保持 Next.js + Prisma + MySQL 单体架构，完成「自主求职者访问 → 注册与登录 → 免费试用 → 简历诊断/面试练习 → 购买固定 AI 次数包 → 渠道支付 → 服务端验签 → 原子发放权益 → AI 调用预留/确认/失败返还 → 订单/用量查询 → 退款与售后 → 后台对账 → 生产部署、监控与恢复」的可验证闭环。

**技术上线就绪不等于合法商业上线。** 真实 AI 和真实支付默认禁用，不得自动启用生产密钥或公网收费。外部行政资质、商户审核、正式隐私条款、实际模型服务数据处理审查和真实小额商户验收须由有权主体完成。

## 2. 当前产品边界

- 独立的 AI 简历分析、真实经历润色、面试练习、求职进度管理和次数包软件服务。
- 不售卖职位、企业联系方式，不提供未经许可的职业介绍/人才撮合，不保证录用。
- 未经授权不得采集、发布第三方招聘信息；旧招聘业务只允许保留历史订单与合法售后。
- 不虚构学历、经验、技能或绩效；模型反馈只供个人练习。
- 避免保存简历和面试原文；如功能需要保存，必须单独设计明示同意、保留期、删除权和安全措施。

## 3. 恢复流程（每次开始执行）

1. 打开当前 job-codexpro 工作树，完整读取 `AGENTS.md`、本文件、`current-task.md`、`handoff.md`、`requirement-matrix.md`、`test-evidence.md`、`release-checklist.md`、`risk-register.md`。
2. 核验真实 Git 状态、远端分支、未提交文件、实际服务与数据库，不直接相信历史检查点。
3. 按需求矩阵及依赖，从最高优先级非 VERIFIED 工作包继续；避免重新规划或重复已通过验收的任务。
4. 每包先补测试（若适用），写实现，跑检查、记录证据，更新矩阵/当前任务/交接，再小批 commit、在许可时 push。
5. 保护其他 Agent 的更改；不删除/覆盖非本人文件，不混提交，不 reset/clean/强推，不在未验收时宣称完成。
6. 记录阻断而不是猜测成功，独立推进不依赖外部密钥或审批的工作。

## 4. Phase 0：基线、安全与质量门禁（P0）

- 项目配置、环境、真实数据库隔离、Next.js/Prisma 类型检查、单元/集成测试和生产构建。
- 权限、订单、AI 用量和财务事务安全；用户数据隔离、输入验证、限流、日志与异常处理。
- 排除支付渠道/AI 服务配置不足造成的错误解锁、模拟付费权益渗透生产、请求并发超扣及崩溃卡账。
- 生产迁移方案与可重复 CI 验证；必须保留测试证据。

## 5. Phase 1：AI 产品能力（P0/P1）

- 文本简历诊断、岗位要求差距、真实经历改写建议、AI 面试题/文字多轮练习/STAR 反馈。
- PDF/DOCX 安全解析、在线编辑及 PDF 导出在核心支付/合规闭环稳定后推进，不得不安全地直接上传敏感材料。
- 安全 LLM Provider 接口：超时、失败、限流、Token/成本记录、输出格式校验、提示词注入和个人数据处理说明。
- 用户明确同意后才调用合规核定的外部服务，缺少资格或密钥时保持禁用，规则示例标明不是 AI。

## 6. Phase 2：支付、次数和售后（P0）

- 1 次免费试用；`STARTER20` 9.9 元/20 次；`PRO100` 29.9 元/100 次，定价由服务端控制。
- 支付宝 PC 和微信 Native：创建、查单、关单、异步回调验证、订单号/商户/币种/金额/渠道/交易号校验、并发与重复通知幂等。
- 权益原子发放和消费，模型失败返还；异常预留人工核对、流程恢复和告警。
- 退款申请、资金回退结果查询、正确撤销剩余权益、自动/人工对账及审计；避免无凭据自动回退。
- 实际小额支付/退款联调必须在测试环境、有效商户与人工授权下完成；不得用 Mock 代替。

## 7. Phase 3：用户和管理运营（P0）

- 注册/登录、邮箱验证、找回密码、会话管理、账户删除、隐私/条款确认。
- 个人订单、余额/用量查询、退款和客服入口、私有求职记录 CRUD。
- 管理后台客户、交易、AI 运行、模型成本、退款、审计、运营统计与异常告警；管理员操作和接口单独验证权限。

## 8. Phase 4：体验与可用性（P1）

- 首页、简历诊断/练习、定价/支付、订单/账务、客服、账户及移动端完整业务路径。
- 浏览器端错误、空状态、加载、死链接、响应式、可访问性、SEO；前端不得声称未实现的能力已经可用。

## 9. Phase 5：部署、安全和上线（P0）

- 独立生产库、受控 Prisma 迁移、CI/CD、HTTPS、备份/恢复演练、健康检查、监控/告警、密钥管理、回滚方案。
- 身份、越权、XSS、CSRF、SSRF、SQL 注入、滥用/限流、文件解析、数据保留和日志脱敏审查。
- 明确国内适用的主体、ICP、电信业务、人力资源服务及生成式 AI、个人信息保护、消费者权益、支付合规门禁。

## 10. 必须具备的真实验收

A. 新用户免费体验，第二次领取拒绝；B. 下单、正确支付、幂等授权、正常消费；C. 假回调、错金额、并发、超时；D. AI 失败/进程异常与账务核对；E. 退款/撤权/对账；F. 跨账户权限隔离；G. 全新预发布环境构建、部署、备份恢复与浏览器回归。

验收状态仅使用 `TODO / IN_PROGRESS / BLOCKED / VERIFIED`；仅有真实测试/审核证据才能标 VERIFIED。技术上线就绪须 P0 无遗留缺陷，资金闭环、支付退款、部署和安全经验证。生产商户及法律审核仍属于外部门禁，不由 Agent 擅自通过。
